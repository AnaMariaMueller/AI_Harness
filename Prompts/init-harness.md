# Update the Claude Code wrappers of this repository's GitHub Copilot customizations
Last updated: 2026-11-24 01:00
You are generating Claude Code wrappers for the GitHub Copilot customizations of the git repository
of the current working directory, and nothing else. Follow the steps in order. Every step is
**check, then apply**: if the desired state already exists, do nothing and report "already ok".
Running this prompt again must produce no changes. Do not commit anything. Do not ask questions
unless a step says "ask".

Not part of this prompt:
- Machine setup (global git excludes, user settings, the commit and shell hooks, connectors, the
  ESAF plugins): `Prompts/setup-machine.md` of the AI_Harness repository. Run it first on a new
  machine.
- Wrappers of the ESAF AI Toolkit plugins: they live at user level (`~/.claude/agents`, `rules`,
  `skills`, `commands`) and are regenerated by `Scripts/Update-EsafPlugins.ps1` of the AI_Harness
  repository after every toolkit publish. This prompt never writes, lists or deletes them.
- Rules that hold in every repository (no AI attribution, delegation, screenshots, shell commands,
  `.gitattributes`, project memory): the always-on rules of the `esaf-core` and `dev-flow` plugins.

## Parameters
- FORBIDDEN_PATTERN (case-insensitive regex for text written into tracked files): `claude|anthropic`
- WRAPPER_DIRS: `agents`, `rules`, `skills` under the TARGET's `.claude/`

## Working rules for this prompt
- Text written into a tracked file (only the `AGENTS.md` block of Step 3) uses neutral wording
  ("the assistant", "the local wrapper folder") and must not match FORBIDDEN_PATTERN.
- Create and change files only with the file tools, as UTF-8 without BOM with LF line endings.
  Merge JSON keys and keep everything else; in markdown with managed blocks replace only the text
  between the markers.
- Generating wrappers from this spec is mechanical: hand it to a small model when one is available.

## Step 0. Locate the repository and the target
- `git rev-parse --show-toplevel` must succeed; stop otherwise. Call the result REPO and its folder
  name NAME.
- **Workspace mode** applies when the parent folder of REPO is not inside a git repository
  (`git -C <parent> rev-parse` fails) and holds both a `CLAUDE.md` and a `.claude/` folder. Then the
  wrappers belong to the workspace, not to the clone: TARGET is the parent folder. Otherwise
  TARGET is REPO (**repository mode**).
- Repository mode: `git check-ignore -q .claude/settings.json` and `git check-ignore -q CLAUDE.md`
  must both succeed. If one fails, stop and report "needs attention: run Prompts/setup-machine.md
  first" — wrappers must never become tracked files.
- Workspace mode: REPO must hold no `.claude/`, `CLAUDE.md` or `CLAUDE.local.md`. If one exists,
  report it and **ask** whether to move it to `TARGET/_archive/repo-claude/<NAME>/` (a `.claude/`
  folder is stored there as `claude-dir/`, so it is never loaded). Continue either way.
- Record the sources in REPO: `.github/copilot-instructions.md`,
  `.github/instructions/*.instructions.md`, `.github/prompts/*.prompt.md`,
  `.github/agents/*.agent.md`, `.github/chatmodes/*.chatmode.md`.

## Step 1. Wrappers
Generate the wrappers into `TARGET/.claude/`, one per source, and regenerate all of them on every
run (overwrite, normalize to LF).

| Source in REPO | Wrapper in `TARGET/.claude/` | Frontmatter mapping |
|---|---|---|
| `.github/instructions/<n>.instructions.md` | `rules/<n>.md` (workspace: `rules/<NAME>-<n>.md`) | `applyTo` -> `paths` (same globs as a YAML list; `**` when absent; workspace: every glob prefixed with `<NAME>/`); body copied |
| `.github/copilot-instructions.md` | repository mode: none, imported by `CLAUDE.md` (Step 2); workspace: `rules/<NAME>-copilot-instructions.md` | workspace: `paths: ["<NAME>/**"]`, `description: Repository instructions of <NAME>`; body copied |
| `.github/agents/<n>.agent.md`, `.github/chatmodes/<n>.chatmode.md` | `agents/<n>.md` | `name` copied (file stem when absent); `description` copied; `model` omitted; `tools` omitted unless the source lists only read-only tools (`read`, `codebase`, `search`, `fetch`, `usages`), then `tools: Read, Grep, Glob, WebFetch`; body copied |
| `.github/prompts/<n>.prompt.md` | `skills/<n>/SKILL.md` | `name: <n>`, `description` copied (or the first body line), `disable-model-invocation: true`; body copied, `${input:...}` placeholders replaced with `$ARGUMENTS` |

Copilot tool names in the body (`#codebase`, `#fetch`, ...) stay as they are.

Marker, directly after the frontmatter:
- Repository mode: `<!-- GENERATED from <source>. Edit the source, then regenerate. -->`
- Workspace mode: `<!-- GENERATED from <NAME>/<source>. Edit the source in the repository, then regenerate. -->`,
  followed by an empty line and
  `> Workspace note: this <agent|skill|rule> works in the \`<NAME>/\` repository of the workspace. Every repository-relative path below (\`AGENTS.md\`, \`.github/\`, source and test folders) is relative to \`<NAME>/\`; run git, build and test commands from that folder (\`git -C <NAME> ...\`).`
  The `description` of agents and skills starts with `[<NAME> repository] `.

Stale wrappers: delete every file in WRAPPER_DIRS whose marker names a source of this repository
(repository mode: any `GENERATED from` marker; workspace mode: `GENERATED from <NAME>/`) that was
not regenerated in this run; a skill folder is deleted as a whole. Never touch a file without such
a marker, and never a wrapper of another repository of the workspace.

Name collisions: when the wrapper path is taken by a file without this repository's marker
(another repository's wrapper, or a hand-written file), do not overwrite it: report it and **ask**
for a name (suggest `<n>-<NAME>`). A repository wrapper with the same name as a user-level plugin
wrapper in `~/.claude` is reported as information: the repository wrapper takes precedence.

## Step 3. Inventory block in `AGENTS.md` (committed, tool-neutral)
Create `REPO/AGENTS.md` if missing. Ensure it has this managed block, regenerated on every run from
the sources actually present:
```markdown
<!-- harness-customizations:begin -->

Source of truth: the customizations under `.github/`. Each one has a generated wrapper of the same
name in the local wrapper folder, outside version control. To change behaviour, edit or add the

edit a wrapper by hand. Shared, cross-project behaviour belongs in a plugin of the team's plugin
marketplace, not in this repository.
| Kind | Source | Wrapper name | Purpose |
|---|---|---|---|
| agent | `.github/agents/<n>.agent.md` | `<n>` | <description from frontmatter> |
| instruction | `.github/instructions/<n>.instructions.md` | rule `<n>` (applies to: <applyTo>) | <description> |

| repository instructions | `.github/copilot-instructions.md` | imported by the local instructions | always on |
<!-- harness-customizations:end -->
```
Rows sorted by kind then name; plugins are not listed. With no sources the block holds the heading
and the sentence "None yet. Add them under `.github/` and regenerate."

A `harness-rules` block (`<!-- harness-rules:begin -->` ... `<!-- harness-rules:end -->`) written
by earlier versions of this prompt is superseded by the always-on rules of `esaf-core` and
`dev-flow`. If one exists, report it and **ask** whether to remove it; remove it only on a yes,
and only when `esaf-core` 1.18.0 or later is installed (its `assistant-conduct` rule carries the
attribution, delegation and screenshot rules).

## Step 4. Memory folder
- Read the `Memory folder:` line of the "Project memory facts" section of `REPO/AGENTS.md`
  (esaf-core 1.18.0 and later; a line under "Dev flow facts" is no longer read). If it is missing,
  report "needs attention: choose the memory folder with `/setup-esaf-toolkit`" and use no memory
  setting.
- Repository mode: merge `"autoMemoryDirectory": "<REPO absolute path>/<memory folder>"` into
  `REPO/.claude/settings.json` (git-ignored).
- Workspace mode: the workspace keeps its own memory setting; the folder is only named in the
  repository's block of Step 2.

## Step 5. Report
Print one table with a row per step: `step | status (already ok / applied / needs attention) | details`.
List every wrapper written, unchanged and deleted, every collision and question, and every file
created or changed, separated into "tracked (review and commit yourself)" and "local, not tracked".
End with these checks:
- `git ls-files -z | xargs -0 grep -IliE "FORBIDDEN_PATTERN"` shows no file this run changed.
- Repository mode: `git check-ignore -q .claude/settings.json` and `git check-ignore -q CLAUDE.md`
  succeed. Workspace mode: REPO holds no `.claude/`, `CLAUDE.md` or `CLAUDE.local.md` (or the
  report names it).
- Every file this run created or changed has no CR (`tr -cd '\r' < <file> | wc -c` prints `0`;
  `grep -c $'\r'` is unreliable in Git Bash) and no BOM (`head -c 3 <file> | od -An -c` does not
  show `357 273 277`).
- For `AGENTS.md`: `git diff --stat` and `git diff -w --stat` agree (no line-ending churn).
